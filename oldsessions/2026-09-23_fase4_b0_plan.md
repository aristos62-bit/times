## 2. Κλειδωμένες αποφάσεις (Q&A 23-09-2026)

### Α — Σημασιολογία διαγραφής (Κατηγοριών/Υποκατηγοριών)

- **Καμία «hard» διαγραφή με JSON/export.** Διαγραφή = **λογική** με προ-έλεγχο.
- **«Μπλοκαρισμένη»** = το αντικείμενο χρησιμοποιείται σε ReceiptLines (`countBlockingReceiptLines`
  / `countByCategoryId`). Τότε το delete icon είναι **greyed-out** με tooltip
  `itemCountTooltip(count)` — **όχι** error μετά το tap (αρχή §1.4: καμία απρόβλεπτη συμπεριφορά).
- **«Καθαρό»** = cascade-delete σε **transaction** (Items→Υποκατηγορίες→Κατηγορία) ως
  **side-effect**, χωρίς νέο UI διαχείρισης ειδών (DESIGN §2.3).
- **FK RESTRICT παραμένει** (`RESTRICT` στα schema) — δεν παραβιάζεται το schema, απλώς
  χαλαρώνει η συμπεριφορά στο επίπεδο της λογικής εφαρμογής.

### Β — Restore & restart (idempotent close)

- **Κανένα DB leak σε κανονικό shutdown.** Το drift `close()` δεν είναι idempotent
  (double-close = σφάλμα). Λύση:
  - Νέο `AppDatabase.closeSafely()` **idempotent** (guard `_closed` flag).
  - `onDispose` στον `appDatabaseProvider` → `db.closeSafely()`.
  - Το restore καλεί **ρητά** `db.closeSafely()` ώστε να κλείσει αλληλεπικαλυπτόμενες
    ανοίξεις πριν αντικαταστήσει το αρχείο βάσης.

### Γ — Εύρος CRUD (κανόνας 3 / §2.0.1 SPoT)

- **ΜΟΝΟ Κατηγορίες / Υποκατηγορίες** (§2.3 DESIGN).
- Το cascade-delete καθαρίζει **orphan Items** ως side-effect (δεν δημιουργείται νέο UI ειδών).

### Δ — Backup format & restore σειρά

- **Backup = `.sqlite`** snapshot μέσω `VACUUM INTO` (drift `customStatement` / sqlite3 backup API)
  — **NOT JSON** (JSON θα ήταν αντίθετο στο SPoT μιας drift βάσης). Export = **ένα `.sqlite`** αρχείο.
- **Restore σειρά (κλειδώθηκε, σειρά που διόρθωσε ο χρήστης)**:
  1. **Validation** ΠΡΙΝ από οτιδήποτε (SQLite magic bytes + πίνακες §2.3:280).
  2. **Confirm dialog** με ρητή προειδοποίηση αντικατάστασης δεδομένων.
  3. **Υποχρεωτικό αυτόματο backup** της τρέχουσας βάσης (safety net).
  4. `closeSafely()` → αντικατάσταση αρχείου → **restart των Riverpod providers**
     (`ref.invalidate(appDatabaseProvider)`) ώστε ΟΛΟ το UI να διαβάσει τα νέα δεδομένα —
     όχι μόνο αντικατάσταση αρχείου χωρίς ανανέωση state (κλασικό λάθος §2.3:282).

### Namespace guard (κανόνας 7 / SPoT)

- Η λειτουργία Backup **ΔΕΝ γράφει ΠΟΤΕ** στον φάκελο `backups/` του project (εκεί πάνε τα
  αρχεία backup βημάτων του project, §1.9). Αντίθετα:
  - **Export Φάσης 4** = file_picker **save dialog** (αρχείο επιλογής χρήστη).
  - **Restore** = file_picker **pick** + auto-backup σε temp/εξωτερική θέση.
